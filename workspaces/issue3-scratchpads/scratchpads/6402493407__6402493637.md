## Feasibility decision memo — 2026-10-25

**Decision: RESTRICT TO MECHANICAL CORE.** Do **not** build an autonomous "semantic context orchestrator" claiming to select all necessary information, detect sufficient context, validate its own summary and know when to stop correctly for arbitrary work. These guarantees have no specified independent correctness oracle. This is **not** a proof of Turing undecidability: finite ID, revision, schema, byte-budget, checksum and provenance checks are decidable; semantic correctness is task-dependent, often empirically measurable on labeled cases, and generally ungrounded or underspecified without external truth. Retain only existing deterministic linkage and explicit-request retrieval conventions; a new runtime is not justified by the available evidence.

**Grounding.** The original research job [Issue #2 / 6402323973](https://github.com/BestNameYet/IssueStack-/issues/2#issuecomment-6402323973), specifically R7, proposes scoped job/pad retrieval, context budgeting, provenance, mailbox correlation and progressive reads. Its [scratchpad](https://github.com/BestNameYet/IssueStack-/issues/3#issuecomment-6402324254) explicitly labels the proposal unimplemented. Existing [AGENTS.md](https://github.com/BestNameYet/IssueStack-/blob/main/AGENTS.md), [Issue #1](https://github.com/BestNameYet/IssueStack-/issues/1), and [Issue #2](https://github.com/BestNameYet/IssueStack-/issues/2) specify exact IDs, typed requirements, readback and a three-issue handshake. The [MCP Collaborative profile standard](https://github.com/BestNameYet/MCP-Collaborative/blob/main/APPLICATION_PROFILE_STANDARD.md) likewise separates deterministic orchestration from semantic/model responsibility and demands independent verification. None of these sources establishes a universal semantic sufficiency oracle or empirical improvement for a proposed context selector.

**Dependence chain:** An unrestricted "include exactly what is important" objective requires correct relevance judgments. "Context sufficient" requires knowing whether any omitted item would change the answer. "Faithful summary" requires comparing the semantic content of the entire source with an abstraction, including omissions. "Stop when complete" depends on those earlier judgments. A model evaluating its own outputs does not create new independent evidence. This is an **oracle/evaluation-specification gap**, not a general reduction to the halting problem. A finite dataset with explicit labeled relevance and fixed scoring is testable; it cannot establish a general semantic guarantee.

### Roles and circularity

- **Producer:** emits authoritative issue/job/task records and external source documents.
- **Mechanical coordinator:** fetches by explicit ID, checks mapping, nonce/revision/authorization, deduplicates exact records and accounts for budget; it cannot certify meaning.
- **Heuristic selector / summarizer:** suggests candidate additions or a synopsis; its output is untrusted, provenance-bearing advice rather than a proof.
- **Worker:** performs the task and must expose uncertainty, missing sources and requirement-level evidence.
- **Verifier:** checks external deterministic facts (exact GitHub IDs, retrieved file versions, executed test output, third-party source, human-labeled gold case). A second LLM reading the same partial context remains **correlated opinion**, not independent truth.

**Adversarial case A — silent omission:** A relevant exception exists only in a late Issue #2 comment. The selector fetches the first five comments and confidently excludes later comments. A verifier shown the same subset cannot discover the omitted exception. A complete count/explicit-ID manifest reveals missing material, but cannot determine by itself whether the missing item matters.

**Case B — false sufficiency:** A job seems answered by AGENTS.md; a recent issue comment overrides the interpretation for that particular nonce. A semantic judge sees only AGENTS.md, declares "enough," and approves the answer. A revision or pinned-reference check catches the omission **only if the override was registered**. No judge can validate an unknown missing source from the same incomplete evidence.

**Case C — self-validating summary:** A summarizer drops a caveat ("not tested end-to-end") and a second model, reading only the summary, approves "fully operational." Byte-level citations of AGENTS.md or the original statement could falsify this particular misquote; a summary-only model vote cannot. A meaningful semantic evaluation requires an independent full-source reviewer or labeled assertions with traceable spans.

3. Budget in bytes/tokens conservatively with a deterministic must-read precedence: governing policy, assigned job/requirements, linked pad, named external references, then optional candidates. Deduplicate exact IDs; never silently truncate required records. Report overflow and make another targeted fetch or request human direction rather than claiming completeness.
4. Offer explicit-ID and keyword navigation, not automatic "semantically complete" retrieval. Persist a compact pointer/receipt/checklist; on resume **rehydrate raw, versioned sources**, not merely a model-written digest. Retain immutable requirement IDs and observed test receipts.
5. Expose uncertainty as an output: "required source unavailable", "budget exceeded", "unindexed external facts may exist", or "semantic completeness unverified". A small baseline can **guarantee linkage, provenance accounting and bounded processing**, but cannot guarantee that all relevant records were read, that a summary preserved every meaning, or that task success was objectively determined.

Most of this protocol already exists in IssueStack's declared AGENTS/Issue #2 handshake. Reuse it manually; do not introduce a new autonomous selector or software component absent demonstrated incremental benefit.

### Early kill tests, bounded evaluation and stop conditions

**Paper kill test 1 (omission):** Put a decision-flipping exception in a document absent from the initial explicit-ID set. Ask whether the proposed algorithm can *guarantee* discovery without enumerating or querying that source. If not, reject the universal relevance/sufficiency guarantee immediately.

**Paper kill test 2 (circular judge):** Give producer, worker and LLM verifier the same incomplete but internally consistent summary. Ask what independent observable would refute the approved answer. If none is named, reject semantic self-certification immediately.

**Paper kill test 3 (mechanical core):** For known IDs, simulate correct mapping, missing pad, mismatched nonce, stale revision and forced budget overflow. The desired outputs are respectively "verified link", "blocked", "blocked", "stale/re-fetch" and "overflow/request more"; these checks are finite and independently gradeable. This is a **specified test design**, not a claim that new automated tests have executed.

**Stopping rule:** Stop investigation of the full semantic controller as soon as an essential guarantee requires an unavailable independently labeled/observable correctness signal and no deterministic substitute can implement that guarantee. Reopen only if someone supplies a restricted task domain with a clear gold standard, measurable baseline, error tolerance, and a meaningful improvement relative to simple direct job/pad retrieval. Benchmark any future narrowed proposal on curated contradiction/omission/stale-link fixtures against manual precise-ID retrieval, measuring missed critical sources, token use and recovery, not self-reported confidence.

**Cost/benefit:** The mechanical core preserves traceability and bounded agent input at low conceptual complexity; broad semantic orchestration adds model calls, circular validation risk, masking of absent sources and new upkeep without proven utility. **Final recommendation: RESTRICT TO MECHANICAL CORE, and NO-GO on semantic guarantees or an automated context-orchestrator implementation now.** No implementation, repo mutation, new queue job or runtime experiment is authorized or performed by this feasibility memo.
